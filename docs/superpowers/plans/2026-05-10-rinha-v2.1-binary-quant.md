# Rinha V2.1 — Binary Quantization + Popcount + Int8 Rerank

> **For agentic workers:** Use superpowers:subagent-driven-development. Steps use `- [ ]` checkboxes.

**Goal:** trocar a busca brute-force int8 atual (p99 ~38 ms local) por uma busca em **dois estágios**: scan binário (1-bit/dim, popcount) sobre os 3M vetores → top-32 candidatos → rerank int8 L2 → top-5 final. Espera-se p99 sub-millisegundo local.

**Architecture:** o index file ganha uma seção nova de **binary codes** (3M × 2 bytes = 6 MB) calculada por threshold per-dim (mediana das 3M referências). A seção int8 existente continua, usada apenas para rerank dos 32 candidatos. Search lê a seção binária linearmente (cabe em L3 com folga, baixíssima latência), depois faz 32 distâncias int8 (irrelevante).

**Tech Stack:** Zig 0.16, `@popCount` builtin (mapeia para `POPCNT` em x86_64), `@Vector(N, T)` para batches AVX2 quando aplicável. Sem libs externas.

---

## Algoritmo

**Quantização binária** (per-dim threshold):
```
para cada dim d in 0..14:
  threshold[d] = mediana dos 3M valores normalizados de dim d
para cada vetor v:
  binary_code[v] = bit d em (v[d] >= threshold[d]) for d in 0..14
  // empacotar em u16 little-endian, bits 14-15 = 0
```

**Hamming search** (hot path):
```
q_bin = quantize_binary(query, threshold)
para cada code in binary_codes:  // 3M × u16
  d = popcount(code XOR q_bin)
  manter top-32 com d menor (heap pequeno)
```

**Rerank**:
```
para cada idx in top_32:
  d = sum((q_int8[i] - ref_int8[idx][i])^2 for i in 0..14)
  manter top-5
```

**Decisão**: igual a V1. `fraud_score = popcount(labels[top5]) / 5`. `approved = fraud_score < 0.6`.

## Mudanças no formato de índice

Versão atual:
```
[Header (32B): magic, num_vectors, dim, reserved]
[labels: ceil(N/8) bytes]
[int8 vectors: N × 14 bytes]
```

Nova versão V2:
```
[Header (32B): magic, num_vectors, dim, reserved]
[thresholds: 14 × f32 = 56 bytes]   // per-dim binary quantization thresholds
[labels: ceil(N/8) bytes]
[binary codes: N × u16 (2 bytes each)]   // 6 MB for N=3M
[int8 vectors: N × 14 bytes]              // 42 MB for N=3M
```

Total novo: ~32 + 56 + 0.4M + 6M + 42M ≈ **48.4 MB** (versus 42.4 MB antes — 6 MB extra para a seção binária).

Magic muda para `0x52494E48413236_02` (versão 2) — força incompatibilidade com índices V1 antigos. Define `pub const magic_v2: u64 = ...`.

## Riscos

1. **Mediana sob streaming**: para 3M valores por-dim, mediana exata exige O(N) memória ou O(N log N) tempo (sort). Para V2.1 vamos **carregar todos os 3M × 14 floats em RAM no builder** (≈ 168 MB), calcular mediana via partition (`std.sort.partition` ou nth_element-equivalent), e descartar. O builder não tem limite apertado de RAM — só os APIs runtime.
2. **Precisão da quantização binária**: 14 bits não são suficientes em alguns casos. Plano B: 28 bits (2-bit/dim) eleva para 4 bytes/vetor, total 12 MB. Decidir com base no smoke ground-truth pós-implementação.
3. **`@popCount` em arm64 (dev)**: builtin existe (`popcount` instruction em ARMv8). Não há regressão local.
4. **Cache-friendliness**: 6 MB de binary codes em scan linear sobre L3 (4 MB no Mac Mini de teste). Usar prefetching seria ideal mas é V2.2.
